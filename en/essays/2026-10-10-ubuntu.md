# After upgrading to Ubuntu 26.10, the sound switched to "dummy output"

2026-10-10

## background

After upgrading to Ubuntu 26.10, my sound suddenly switched to "dummy output."

At the `lspci` level, the Intel audio device is recognized correctly. However, when I run `alsamixer`, I get this error.

```text
[W] pw.conf | scandir /home/ユーザー名/.config/pipewire/client.conf.d failed: 許可がありません
ミキサーを開けません: ホストが落ちています
```

It wasn't a hardware failure, but rather **a permission bug in the audio management server (PipeWire) configuration file or a corrupted cache**.

`alsamixer -c 1` Here, I'll summarize the steps for restoring audio completely, starting from a state where the system barely boots.

## Troubleshooting Steps

### 1. Modifying Permissions for the Settings Folder

Correct the permissions of the configuration file causing the error, and add the user to the appropriate group.  
(Be sure to change `ユーザー名` to match your environment.)

```bash
# ホームディレクトリ内の設定ファイルの所有権をまとめて修正
sudo chown -R ユーザー名:ユーザー名 ~/.config

# オーディオデバイスを操作するグループにユーザーを追加
sudo usermod -aG audio,video ユーザー名
```

> **Note:** In environments after migrating to PipeWire, you may encounter an error stating that the `pulse` group does not exist; however, this is by design, so you can safely ignore it.

### 2. Clearing the Cache and Settings

Delete all old settings and cache data from the audio server.

```bash
rm -rf ~/.config/pipewire ~/.config/pulse ~/.local/state/pipewire ~/.local/state/wireplumber
```

### 3. Restart the audio service

Once the system is in a clean state, restart the PipeWire-related services under the user's permissions. (`sudo` is not required.)

```bash
# ユーザー用サービスの構成をリロード
systemctl --user daemon-reload

# 必要なサービスをすべて有効化
systemctl --user enable pipewire pipewire-pulse wireplumber

# サービスを今すぐ起動
systemctl --user start pipewire pipewire-pulse wireplumber
```

### 4. Verify Startup

```bash
systemctl --user status pipewire-pulse wireplumber
```

If **`active (running)`** appears in green, it means the operation was successful. You can exit using `q`.

## conclusion

Following these steps, PipeWire—which had stopped working—started up normally, the “Dummy Output” disappeared from the settings screen, and sound began coming from the actual speakers.

If your sound card appears in the hardware list but there is no sound or you cannot open the mixer, please try resetting the audio server settings first.
