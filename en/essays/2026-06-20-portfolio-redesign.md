# Portfolio redesign

2026.06.20 ・ Rainweed Garden Portfolio

## 1. What I started

He was planning a catalog site that would automatically synchronize project metadata using his numerous GitHub repositories as the "single source of truth." I was trying to build a pipeline that would extract information from the repository's README and configuration files and use GitHub Actions to automatically update the portfolio.

## 2. What was wrong

As I was building synchronization scripts and pipelines, I started to feel that something wasn't right. As I became more passionate about automation design, I felt strange that an inorganic "catalog" that was just a list of completed repositories was being created. However, what I really wanted to convey was not ``introducing completed products,'' but ``the approach and thought process when creating software to solve problems,'' and I realized that this is where the real pleasure of creating software lies.

## 3. Policy change

Therefore, we went back to the drawing board with all automated pipelines and complex UI construction, and changed the focus of the site from a ``project catalog'' to a ``portfolio that describes the thinking process.'' GitHub plays a supporting role (a place for artifacts), and the process is the main focus. I placed Markdown files directly and moved to a simple text layout centered on text.

## 4. Results

Freed from the constraints of complex codes and rules that come with building an automated system, I was able to pivot to a portfolio site that conveyed my own "temperature". I would like to leave here not only the finished products, but also the traces of my thoughts on unresolved projects.
