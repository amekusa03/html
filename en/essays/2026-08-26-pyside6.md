# Try PySide6 with QtCreator

## things you end up doing

I am using Qt Creator for PySide6 development. It's convenient, but I end up doing it every time.

I end up trying to create a slot with QtDesigner. Perhaps I can't get over the C++ feel, but every time I place a button I reach for the signal/slot editor. Then, when building, you will get an angry message saying that the header file is missing. That's right, there are no headers in Python.

## the right way

The policy is simple. QtDesigner focuses only on screen layout. Only place buttons etc. and set `objectName` (example: `pushButton_submit`), but do not touch the slots.

Connections between signals and slots are done in the Python code.

```python
from PySide6.QtCore import Slot
from PySide6.QtWidgets import QApplication, QMainWindow
from mainwindow import Ui_MainWindow

class MainWindow(QMainWindow, Ui_MainWindow):
    def __init__(self):
        super().__init__()
        self.setupUi(self)
        self.pushButton.clicked.connect(self.on_submit_clicked)  # self から直接アクセス

    @Slot()
    def on_submit_clicked(self):
        print("ボタンがクリックされました")

if __name__ == "__main__":
    app = QApplication([])
    window = MainWindow()
    window.show()
    app.exec()
```

One thing to note. Write `self.pushButton` instead of `self.ui.pushButton`. Since it has multiple inheritance from `Ui_MainWindow`, it can be accessed directly without going through `ui`.

## Another way

Another option is to automatically connect using naming conventions. If you change the slot method name to `on_オブジェクト名_シグナル名`, you don't have to explicitly write `connect`.

```python
from PySide6.QtWidgets import QApplication, QMainWindow
from mainwindow import Ui_MainWindow

class MainWindow(QMainWindow, Ui_MainWindow):
    def __init__(self):
        super().__init__()
        self.setupUi(self)

    def on_pushButton_clicked(self):
        print("ボタンがクリックされました")

if __name__ == "__main__":
    app = QApplication([])
    window = MainWindow()
    window.show()
    app.exec()
```

Just match the names in the derived class. I can understand how it works, but I'm a little concerned about being bound by naming rules.
