# Exception handling in C++, C#, and Python

2026-08-19

When developing in different languages, you will notice that the way to write exception handling differs depending on the language. Therefore, we have summarized exception handling in the representative languages ​​C++, C#, and Python.
There are major differences in exception handling in C++, C#, and Python in **syntax**, **thrown types**, and **philosophy**.

Below is a comparison table and detailed features and code examples of each language.

## Comparison list of exception handling

| Comparison item | C++ | C# | Python |
| :--- | :--- | :--- | :--- |
| **Keywords** | `try`, `catch`, `throw` | `try`, `catch`, `finally`, `throw` | `try`, `except`, `else`, `finally`, `raise` |
| **Throwable types** | **Any type** (`int`, `string`, objects, etc.) | `System.Exception` derived classes only | `BaseException` derived classes only |
| **Post-processing/cleanup** | **RAII (destructor)**<br>*(finally does not exist)* | `finally` block <br>`using` syntax (`IDisposable`) | `finally` block <br>`with` syntax (context manager) |
| **Catch all exceptions** | `catch (...)` | `catch (Exception)` or `catch` | `except Exception:` or `except:` |
| **Unique/specific features** | `noexcept` specifier | Exception filter (`catch ... when`) | `try...else` block <br> exception chain (`raise ... from ...`) |
| **Error Handling Culture** | Exceptions are used only in **truly exceptional situations** | Exceptions are used for relatively heavy-duty error handling | Frequently used |

## Code comparison and features of each language

### C++

There is no **`finally` block in C++**. Instead, resources are released by using a mechanism (RAII) in which the **destructor** is automatically called when exiting the scope.

```cpp
#include <iostream>
#include <stdexcept>
#include <string>

// リソース管理の例
class ResourceGuard {
public:
    ResourceGuard() { std::cout << "リソース確保\n"; }
    ~ResourceGuard() { std::cout << "デストラクタで自動解放\n"; } // スタック展開時に自動実行
};

void testFunction(int value) noexcept(false) {
    ResourceGuard guard; // スコープを抜ける時に必ず解放される
    
    if (value < 0) {
        throw std::invalid_argument("値が負です"); // 標準例外オブジェクトを投げる
        // throw 404; // C++では int や string など任意の値も投げられる
    }
}

int main() {
    try {
        testFunction(-1);
    } catch (const std::invalid_argument& e) {
        std::cerr << "Caught: " << e.what() << std::endl;
    } catch (...) {
        // すべての例外をキャッチ
        std::cerr << "Unknown exception caught" << std::endl;
    }
    return 0;
}
```

### C \#

C# supports the full set of `try-catch-finally`. It can only be thrown by classes derived from `System.Exception`. Also, the **exception filter (`when`)** introduced from C# 6.0 is powerful.

```csharp
using System;
using System.IO;

class Program {
    static void Main() {
        // using ステートメント（IDisposable による RAII に似た自動リソース解放）
        try {
            ProcessFile("non_existent_file.txt");
        } 
        // 例外フィルター (when 条件式)
        catch (FileNotFoundException ex) when (ex.FileName.EndsWith(".txt")) {
            Console.WriteLine($"テキストファイルが見つかりません: {ex.Message}");
        } catch (Exception ex) {
            Console.WriteLine($"その他のエラー: {ex.Message}");
        } finally {
            Console.WriteLine("後処理（必ず実行される）");
        }
    }

    static void ProcessFile(string path) {
        if (!File.Exists(path)) {
            throw new FileNotFoundException("ファイルが存在しません", path);
        }
    }
}
```

### Python

In Python, use `except` instead of `catch` and `raise` instead of `throw`.
The biggest feature is that there is a **`else` block** that is executed only if no exception occurs.

```python
def process_data(data, key):
    try:
        # 例外が発生しうる処理
        val = data[key]
    except KeyError as e:
        # 特定の例外処理
        print(f"キーが見つかりません: {e}")
    except Exception as e:
        # その他の汎用例外
        print(f"予期せぬエラー: {e}")
    else:
        # tryブロックで【例外が発生しなかったときだけ】実行される
        print(f"成功: 取得した値は {val}")
    finally:
        # 必ず実行される
        print("処理完了")

# with 構文 (コンテキストマネージャによる自動リソース解放)
try:
    with open("example.txt", "r") as f:
        content = f.read()
except FileNotFoundError:
    print("ファイルがありません")
```

## A deep dive into the key differences

### Throwable type (throw / raise)

* **C++**: In addition to class objects, you can also throw values ​​of any type, such as `int`, `double`, `const char*`, etc. (However, in practice, it is recommended to use a class derived from `std::exception`.)
* **C#**: Only objects that inherit from `System.Exception`.
* **Python**: Only instances of classes that inherit from `BaseException` (usually `Exception`).

### Idea of ​​resource release (RAII vs finally / with / using)

* **C++ (RAII philosophy)**: `finally` keyword does not exist. When an exception is thrown, stack unwinding occurs, and the destructors of local variables are called in order to safely free resources.
* **C# (finally + using)**: In addition to an explicit `finally` block, objects that implement `IDisposable` automatically have `Dispose()` called using the `using` syntax.
* **Python (finally + with)**: Free resources using explicit `finally` blocks as well as the `with` syntax for objects with context managers (`__enter__` / `__exit__`).

### Python-specific `else` and EAFP culture

* **`try...else`**: You can separate the code that you want to execute only when the process in `try` is successful. Since the range of `try` can be narrowed down to the minimum, catching an exception from an unintended location can be prevented.
* **EAFP culture**: In Python, the style of ``execute first and catch the exception (EAFP)'' is preferred over ``check with `if` in advance (LBYL)''. Exceptions are built into the control flow itself, such as when determining the end of an iterator (`StopIteration`) or when referencing a dictionary key.

### C#-specific exception filter (`when`)

* In C#, you can **test the condition before unwinding the stack** by writing `catch (Exception ex) when (条件)`. This allows efficient log output and capture only under specific conditions.

## summary

* **C++**: **Lightweight & RAII Principles**. Resource management is basically done by destructor, and it does not have `finally`. Can throw any type.
* **C#**: **Strict & Feature Rich**. `Exception` Limited to derived objects, flexible control with `finally` / `using` / `when` (exception filters).
* **Python**: **EAFP thought & expressiveness**. `except` / `raise` / `else` / `with` syntax. Use exceptions on a daily basis as a control flow.

### Extra: Exception handling not recommended

* We do not recommend enclosing multiple processes in a `try` block, as it will be impossible to identify which process caused the exception.
* Creating large objects in `catch` or `finally` blocks is not recommended as the release process may not be performed reliably.
  * If you create a large object within the scope of an exception handler, it will normally be freed when you exit the scope. However, if further exceptions occur within that scope, they may not be released properly, potentially causing a resource leak.
