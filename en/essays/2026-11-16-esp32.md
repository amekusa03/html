# Observing the Turning Point for ESP-IDF: The Evolution to v6 and the Deliberate Choice to Stay Where We Are for Now

2026-11-16

## "The Current Version"—Something That Suddenly Caught My Attention

A DIY air conditioner automation system I built using an ESP32-C3, a temperature and humidity sensor (SHT30/31), and the SwitchBot API. When I opened the project for the first time in a while, I suddenly wondered, “Come to think of it, what version of ESP-IDF am I using right now?”

When I checked the build configuration in PlatformIO, I found that the currently running environment was **ESP-IDF `v5.5.4`** (GCC 14.2.0).

So, when I looked into the latest developments, I found that Espressif, the original developer, had already released **`v6.1`**, which had undergone a major update , and PlatformIO’s `platform-espressif32` had also achieved compatibility with v6.1 in `framework = espidf` with its latest version, **v8.0.0**.

I started to think, “Since I’m here, maybe I should upgrade to the latest version,” but as I read through the new features and changes in the v6 series, I decided to hold off on upgrading this time and stick with my current setup.

## The Evolution of ESP-IDF v6 with an Eye Toward the Next Generation

The v6 series (v6.0 / v6.1), a major version update, includes several attractive improvements designed with future embedded development in mind.

- **The Standard C Library Moves to `Picolibc`**: The lightweight `Picolibc`, optimized for embedded systems, has become the standard, replacing the long-used `Newlib`. This is a welcome development, as it reduces Flash usage, heap allocations, and stack consumption during I/O operations such as those involving `printf`.
- **Toolchain and Development Environment Updates**: The compiler has been upgraded to **GCC 15.1.0**, and the cross-platform installer **EIM (ESP-IDF Installation Manager)** has also been introduced.
- **Full Support for Next-Generation Chips**: The **ESP32-C5** and **ESP32-C61**, which support 2.4 GHz/5 GHz dual-band Wi-Fi 6, are now officially supported, paving the way for a new product lineup.

If I were starting a new project from scratch, this is something I’d definitely want to try. However, when it comes to migrating an existing project that’s already up and running, the situation is a little different.

## Modernizing the Design and Its Impact on the Existing Code

A glance at the migration guide reveals that the update from v5.x to the v6 series marks a major turning point, involving the streamlining of legacy specifications that have accumulated over the years and a modern redesign of the entire framework.

The first area affected is the overhaul of the encryption system.
With the security infrastructure updated to **Mbed TLS v4.0**, encryption processing has been standardized using the **PSA Crypto API**. The traditional functions that users have long been familiar with—such as `mbedtls_sha*` and `mbedtls_md*`—have served their purpose and have been phased out.

Actually, this was the biggest change I had to make to my homemade air conditioner control system.
In SwitchBot API v1.1, the signature (`sign`) added to the request header had to be generated using **HMAC-SHA256** , and I had implemented this by directly calling `mbedtls/md.h` from within `main.cpp`.

```cpp
// main.cpp 内の SwitchBot API v1.1 署名生成コード（ESP-IDF v5.x）
mbedtls_md_context_t ctx;
mbedtls_md_type_t md_type = MBEDTLS_MD_SHA256;

mbedtls_md_init(&ctx);
mbedtls_md_setup(&ctx, mbedtls_md_info_from_type(md_type), 1);
mbedtls_md_hmac_starts(&ctx, (const unsigned char *)secret.c_str(), secret.length());
mbedtls_md_hmac_update(&ctx, (const unsigned char *)data.c_str(), data.length());
mbedtls_md_hmac_finish(&ctx, hmacResult);
mbedtls_md_free(&ctx);
```

If you're migrating to the v6 series, you'll need to rewrite this section as well to follow the new convention using `psa_crypto_init()` and `psa_mac_compute()`.

In addition, peripheral device drivers and component configurations have been neatly organized.
The legacy drivers (such as the old ADC, I2S, RMT, timer groups, etc.) have been fully replaced by the new `esp_driver_*` framework, and some features—such as `cJSON`—have been separated from the core, evolving into a modular structure where only the necessary components are loaded via the ESP Component Registry.

While this streamlining makes perfect sense from a framework perspective, if your existing code or external libraries rely on the legacy API, you’ll likely need to proceed cautiously until the supporting libraries have all been updated.

## The peace of mind that comes from knowing the Arduino Core is using the “v5.5 series”

Another helpful point was the differences in the base versions of each framework on PlatformIO's latest platform (`platform-espressif32 v8.0.0`).

- If you select **`framework = espidf`**: The latest **ESP-IDF `v6.1`**
- If you select **`framework = arduino`**: Even with the latest Arduino Core `v3.3.12`, the internal base is **ESP-IDF `v5.5.5`**

Even within the Arduino ecosystem, which supports a vast number of sensor and communication libraries, it is evident that the project prioritizes compatibility and stability, using the mature v5.5 series as its foundation.

## Part of the fun is figuring out which versions are “outdated but stable.”

Whenever a new version comes out, I can’t help but want to upgrade, but when it comes to systems like home appliance controls—which work quietly behind the scenes in our daily lives—there’s nothing more appreciated than “what’s working today continuing to run quietly and without change tomorrow.”

The **ESP-IDF `v5.5.4`** we’re currently using is a well-balanced generation that’s sufficiently up-to-date in terms of functionality and integrates seamlessly with existing library resources. Since it will continue to be maintained as a Long-Term Support (LTS) product until around 2028, it’s the ideal environment for running existing systems.

I’ve decided to save the new v6 series for a new experimental project I’ll be setting up soon, and for this system that monitors the air conditioner in my room, I’ll stick with the v5.5 series—which I’m already familiar with—for a little while longer. Taking the time to pause and observe these “tides of technology” is one of the quiet pleasures unique to independent development.
