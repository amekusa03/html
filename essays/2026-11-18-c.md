# 技術の変遷とC++/CLIの衝撃 〜MS-Cから最新C#（.NET 10）へ至る道〜

2026-11-18

## 進化する開発環境と「直感的なコーディング」

最近、開発環境をVisual Studio 2022から2026へとアップデートし、ターゲットフレームワークも従来の .NET Framework 4.7 から一気に最新の **.NET 10** へと移行した。

最新版のC#を触っていて何より感じるのは、**「非常に直感的で書きやすくなった」**ということだ。定型的なボイラープレートコードが減り、言語仕様そのものが洗練されたことで、思考を妨げられずに本来のロジック構築へ没頭できる。開発効率が一段上がったのを肌で実感している。

## MS-CからMFC、そしてモダンC#へ

思えば、私のプログラミングの原点は **MS-C（Microsoft C）** の時代にあった。

- **MS-DOS時代**：640KBというコンベンショナルメモリの壁と戦いながら、セグメントとオフセット（`near` / `far` ポインタ）を常に意識し、VRAMやハードウェア割り込みを直接叩いていた頃。
- **Windows / MFC時代**：`CWinApp` や `CDocument` / `CView` のドキュメント・ビュー構造、メッセージマップを駆使し、「C++とMFCこそがWindowsアプリケーション開発の王道だ」と信じてコードを書いていた頃。

当時の「ハードウェアと直結している感覚」や、1バイト単位でメモリを切り詰めて管理する厳密さは、エンジニアとしての確かな血肉になっている。しかし、ガベージコレクション（GC）や洗練された非同期処理、充実したエコシステムを備えた現代の **C# / .NET 10** の世界から見れば、まさに次元が違うほどの隔世の感がある。

## 久々のC++/CLIで味わった衝撃

そんな快適なC#ライフを送っていた矢先、仕事で **C++（C++/CLI / .NET 7）** を扱う機会があった。そこで私は、思うように手が進まない自分自身に苦笑することになる。

引き継いだソースコードを開いた瞬間、そこには現代のC#では意識せずに済む「ネイティブC++と.NETの境界線」が生々しく広がっていたのだ。

### `ref class` と `gcnew` への気遣い

C#であれば単に `class` と宣言し、`new` でインスタンス化すれば、あとはガベージコレクションが背後ですべて良きに計らってくれる。だが、C++/CLIではそうはいかない。

- マネージドなクラスであることを示す **`ref class`**
- GCの管理下にオブジェクトを生成する **`gcnew`**
- 従来のC++ネイティブヒープに確保する通常の **`new`**

「このインスタンスはマネージドなのか、アンマネージドなのか」「ポインタの追跡ハンドル（`^`）か、生のポインタ（`*`）か」「メモリのライフサイクルはどうなっているのか」――オブジェクトを1つ扱うだけでも、常に意識の片隅をメモリ管理に占有されてしまう。

### 配列を `++` で進めるポインタ演算

さらに思わず声が出そうになったのが、配列の走査コードだった。

現代のC#であれば `foreach` や LINQ、あるいはシンプルなインデックスアクセスで安全かつ直感的に書くところだが、目の前のコードには**ポインタ演算で配列アドレスを `++`（インクリメント）しながら進める古き良き記法**がそのまま残っていた。

それを見た瞬間、猛烈な懐かしさと同時に、「これを現代の現場で安全に読み解き、触るのか……」という心地よい緊張感が入り混じり、思わず**「おぉ……」**と声が漏れてしまった。

## 隠蔽された複雑さと、先人たちの工夫

今回の体験を通じて、普段何気なく恩恵に預かっているモダンC#が、いかに多くの複雑さを裏側に隠し、開発者を不毛なミスから守ってくれているかを改めて思い知らされた。

| 比較項目 | モダン C# (.NET 10) | C++/CLI (.NET 7) |
| :--- | :--- | :--- |
| **クラス定義・生成** | `class` / `new` で統一 | `ref class` / `gcnew` とネイティブ `new` の混在 |
| **メモリ・参照** | GCが自動管理（普段は意識不要） | マネージドハンドル（`^`）と生ポインタ（`*`）の共存 |
| **コレクション操作** | `foreach` や LINQ で安全・直感的 | インデックス走査やポインタのインクリメント（`++`） |
| **開発の主眼** | 業務ロジックの本質に集中できる | メモリ空間や境界線の整合性を常に意識する |

MS-CやMFCの時代、私たちはこの「ポインタやメモリへの気遣い」を呼吸のように当たり前のものとして乗りこなしていた。C#という完成度の高い環境にすっかり馴染んだ今だからこそ、久しぶりに触れたC++/CLIのコードは、まるでタイムカプセルを開けたかのような新鮮な驚きを届けてくれた。

泥臭くも奥深い低レイヤーの苦労を知っているからこそ、現代の言語やフレームワークがもたらしてくれる進化のありがたみが身に染みる。そんな自らのエンジニアとしての歩みを、静かに再確認できたひとときだった。
