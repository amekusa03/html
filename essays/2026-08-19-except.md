# C++、C#、Python の例外処理

2026-08-19

異なる言語で開発していると、例外処理の書き方が言語によって違うことに気づく。そこで、代表的な言語である C++、C#、Python の例外処理についてまとめた。
C++、C#、Python の例外処理は、**構文**・**投げられる型**・**思想** において大きな違いがある。

以下に比較表と各言語の詳しい特徴・コード例をまとめる。

## 例外処理の比較一覧表

| 比較項目 | C++ | C# | Python |
| :--- | :--- | :--- | :--- |
| **キーワード** | `try`, `catch`, `throw` | `try`, `catch`, `finally`, `throw` | `try`, `except`, `else`, `finally`, `raise` |
| **投げられる型** | **任意の型** (`int`, `string`, オブジェクト等) | `System.Exception` の派生クラスのみ | `BaseException` の派生クラスのみ |
| **後処理・クリーンアップ** | **RAII (デストラクタ)**<br>*(finallyは存在しない)* | `finally` ブロック<br>`using` 構文 (`IDisposable`) | `finally` ブロック<br>`with` 構文 (コンテキストマネージャ) |
| **すべての例外を捕捉** | `catch (...)` | `catch (Exception)` または `catch` | `except Exception:` または `except:` |
| **独自・特有機能** | `noexcept` 指定子 | 例外フィルター (`catch ... when`) | `try...else` ブロック<br>例外連鎖 (`raise ... from ...`) |
| **エラー処理の文化** | 例外は**本当に例外的な事態**でのみ使用 | 例外は比較的重いエラー処理として使用 | 頻繁に使用 |

## 各言語のコード比較と特徴

### C++

C++ には **`finally` ブロックは存在しない**。その代わりにスコープを抜ける際に**デストラクタ**が自動的に呼び出される仕組み（RAII）を利用してリソースを解放する。

```cpp
#include <iostream>
#include <stdexcept>
#include <string>

// リソース管理の例
class ResourceGuard {
public:
    ResourceGuard() { std::cout << "リソース確保\n"; }
    ~ResourceGuard() { std::cout << "デストラクタで自動解放\n"; } // スタック展開時に自動実行
};

void testFunction(int value) noexcept(false) {
    ResourceGuard guard; // スコープを抜ける時に必ず解放される
    
    if (value < 0) {
        throw std::invalid_argument("値が負です"); // 標準例外オブジェクトを投げる
        // throw 404; // C++では int や string など任意の値も投げられる
    }
}

int main() {
    try {
        testFunction(-1);
    } catch (const std::invalid_argument& e) {
        std::cerr << "Caught: " << e.what() << std::endl;
    } catch (...) {
        // すべての例外をキャッチ
        std::cerr << "Unknown exception caught" << std::endl;
    }
    return 0;
}
```

### C \#

C# は `try-catch-finally` のフルセットをサポートしている。投げることができるのは `System.Exception` の派生クラスに限られる。また、C# 6.0 から導入された**例外フィルター (`when`)** が強力である。

```csharp
using System;
using System.IO;

class Program {
    static void Main() {
        // using ステートメント（IDisposable による RAII に似た自動リソース解放）
        try {
            ProcessFile("non_existent_file.txt");
        } 
        // 例外フィルター (when 条件式)
        catch (FileNotFoundException ex) when (ex.FileName.EndsWith(".txt")) {
            Console.WriteLine($"テキストファイルが見つかりません: {ex.Message}");
        } catch (Exception ex) {
            Console.WriteLine($"その他のエラー: {ex.Message}");
        } finally {
            Console.WriteLine("後処理（必ず実行される）");
        }
    }

    static void ProcessFile(string path) {
        if (!File.Exists(path)) {
            throw new FileNotFoundException("ファイルが存在しません", path);
        }
    }
}
```

### Python

Python では `catch` の代わりに `except` を使い、`throw` の代わりに `raise` を使う。
最大の特徴は、例外が発生しなかった場合にのみ実行される **`else` ブロック**が存在することである。

```python
def process_data(data, key):
    try:
        # 例外が発生しうる処理
        val = data[key]
    except KeyError as e:
        # 特定の例外処理
        print(f"キーが見つかりません: {e}")
    except Exception as e:
        # その他の汎用例外
        print(f"予期せぬエラー: {e}")
    else:
        # tryブロックで【例外が発生しなかったときだけ】実行される
        print(f"成功: 取得した値は {val}")
    finally:
        # 必ず実行される
        print("処理完了")

# with 構文 (コンテキストマネージャによる自動リソース解放)
try:
    with open("example.txt", "r") as f:
        content = f.read()
except FileNotFoundError:
    print("ファイルがありません")
```

## 主な違いのディープダイブ

### 投げられる型 (throw / raise)

* **C++**: クラスオブジェクトだけでなく、`int`, `double`, `const char*` など**あらゆる型の値を投げる**ことができる。（ただし実務上は `std::exception` の派生クラスを投げるのが推奨される）
* **C#**: `System.Exception` を継承したオブジェクトのみ。
* **Python**: `BaseException` (通常は `Exception`) を継承したクラスのインスタンスのみ。

### リソース解放の思想 (RAII vs finally / with / using)

* **C++ (RAII思想)**: `finally` キーワードは存在しない。例外が投げられるとスタック展開 (Stack Unwinding) が起き、ローカル変数のデストラクタが順番に呼ばれて安全にリソースが解放される。
* **C# (finally + using)**: 明示的な `finally` ブロックのほか、`IDisposable` を実装したオブジェクトには `using` 構文を使うことで自動的に `Dispose()` が呼ばれる。
* **Python (finally + with)**: 明示的な `finally` ブロックのほか、コンテキストマネージャ (`__enter__` / `__exit__`) を備えたオブジェクトに `with` 構文を使うことでリソースを解放する。

### Python 特有の `else` と EAFP 文化

* **`try...else`**: `try` 内の処理が成功したときだけ実行したいコードを分離できる。`try` の範囲を最小限に絞り込めるため、意図しない場所からの例外捕捉を防げる。
* **EAFP 文化**: Python では「あらかじめ `if` でチェックする (LBYL)」よりも「とりあえず実行して例外をキャッチする (EAFP)」スタイルが好まれる。イテレータの終了判定 (`StopIteration`) や辞書のキー参照など、制御フロー自体に例外が組み込まれている。

### C# 特有の例外フィルター (`when`)

* C# では `catch (Exception ex) when (条件)` と書くことで、**スタックを巻き戻す前に条件を判定**できる。これにより、ログ出力や特定の条件下のみの捕捉が効率よく行える。

## まとめ

* **C++**: **軽量＆RAII原則**。デストラクタによるリソース管理が基本で、`finally` は持たない。任意の型を throw 可能。
* **C#**: **厳密＆機能豊富**。`Exception` 派生オブジェクト限定、`finally` / `using` / `when` (例外フィルター) による柔軟な制御。
* **Python**: **EAFP思想＆表現力**。`except` / `raise` / `else` / `with` 構文。制御フローとしても日常的に例外を活用。

### 番外編：推奨しない例外処理

* 複数の処理をまとめて `try` ブロックで囲ってしまうと、どの処理で例外が発生したのか特定できなくなるため推奨しない。
* `catch` ブロックや `finally` ブロックの中で大きなオブジェクトを生成することは、解放処理が確実に行われない可能性があるため推奨しない。
  * 例外処理のスコープ内で大きなオブジェクトを生成した場合、通常はそのスコープを抜ける際に解放される。しかし、そのスコープ内でさらに例外が発生した場合には適切に解放されず、リソースリークの原因となる可能性がある。
