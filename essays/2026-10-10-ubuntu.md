# Ubuntu 26.10にしたらサウンドが「ダミー出力」になった

2026-10-10

## 経緯

Ubuntu 26.10 にアップグレードしたら、突然サウンドが「ダミー出力」になってしまった。

`lspci` レベルでは Intel のオーディオデバイスがきちんと認識されている。なのに `alsamixer` を叩くと、こんなエラーが出る。

```text
[W] pw.conf | scandir /home/ユーザー名/.config/pipewire/client.conf.d failed: 許可がありません
ミキサーを開けません: ホストが落ちています
```

ハードウェアの故障ではなく、**音声管理サーバー（PipeWire）の設定ファイルの権限バグやキャッシュの破損**が原因だった。

`alsamixer -c 1` では辛うじて起動する状態から、完全にオーディオを復活させるまでの手順をまとめておく。

## 解決手順

### 1. 設定フォルダの権限修正

エラーの原因となっている設定ファイルの権限を直し、ユーザーを適切なグループに追加する。  
（`ユーザー名` は自分の環境に合わせて変えること）

```bash
# ホームディレクトリ内の設定ファイルの所有権をまとめて修正
sudo chown -R ユーザー名:ユーザー名 ~/.config

# オーディオデバイスを操作するグループにユーザーを追加
sudo usermod -aG audio,video ユーザー名
```

> **Note:** PipeWire 移行後の環境では `pulse` グループが存在しないというエラーが出ることがあるが、仕様なので無視して問題ない。

### 2. キャッシュと設定のクリーンアップ

オーディオサーバーの古い設定やキャッシュを丸ごと削除する。

```bash
rm -rf ~/.config/pipewire ~/.config/pulse ~/.local/state/pipewire ~/.local/state/wireplumber
```

### 3. オーディオサービスの再起動

クリーンな状態にしたら、PipeWire 関連サービスをユーザー権限で起動し直す。（`sudo` は不要）

```bash
# ユーザー用サービスの構成をリロード
systemctl --user daemon-reload

# 必要なサービスをすべて有効化
systemctl --user enable pipewire pipewire-pulse wireplumber

# サービスを今すぐ起動
systemctl --user start pipewire pipewire-pulse wireplumber
```

### 4. 起動確認

```bash
systemctl --user status pipewire-pulse wireplumber
```

緑色で **`active (running)`** と表示されていれば成功だ。`q` で抜けられる。

## 結論

この手順で、落ちていた PipeWire が正常に起動し、設定画面から「ダミー出力」が消えて本来のスピーカーから音が出るようになった。

ハードウェアとしてはサウンドカードが見えているのに音が出ない・ミキサーが開けないときは、まずオーディオサーバーの設定初期化を試してみてほしい。
