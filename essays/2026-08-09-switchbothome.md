# + SwitchBot Smart Home を使う

2026-08-09

## 概要

前回、ESP32-C3でGoogle Home 連携の照度センサーを作ったが、
1日1回の照明の制御だけでは、アンダースペックすぎる。
大きな不具合が発生しなかったことも、不十分に感じる要因の1つであろう。

そこで、今回は照度センサーESP32-C3にWebサーバーを設定し、SwitchBot Smart Home を機能追加しようと考えた。
論理的には可能なはずで、以前からESP32でWebサーバーを構築したいと思っており、ちょうど良い機会だと考えて挑戦することにした。

## SwitchBotのAPIを叩くための、地味だが避けて通れない儀式

SwitchBotのOpen API v1.1は、HMAC-SHA256による署名付きリクエストを要求してくる。tokenとsecret、ミリ秒精度のタイムスタンプ、ランダムなnonceを組み合わせて署名を作る、という認証の様式美である。ESP32側ではmbedtlsを使ってこれを実装した。

最初は理解せず、Web UIのボタンを押しては「401 unauthorized」を返され続けていたが、原因を正しく特定して対処すると、すんなりと動作した。正確なタイムスタンプが必須とのことで、ESP32でNTPによる時刻同期を行った。マイコンの内蔵時計はあてにならず、ここは素直にesp_netif_sntpに任せる。地味な処理だが、これが狂っていると認証がすべて失敗するようだ。

## UIとフォールバックという、優しさの話

Web UIはAIに頼んだら、ガラスっぽい半透明デザイン（Glassmorphism）で組んでくれた。照度のリアルタイム表示バナーと、SwitchBotの家電操作カードを1つの画面にまとめている。せっかく作るのなら、見た目もそれなりに気を遣いたい。

Wi-Fi設定がまだない、あるいは接続に失敗した場合は、自動的にSoftAPモード（`ESP32-SwitchBot-Setup`、`192.168.4.1`）で立ち上がるようにした。設定情報はNVSに書き込み、一度設定すれば次回起動時も覚えているようにした。また、GPIO9のボタンを3秒長押しすればMatterとNVSの設定を丸ごとリセットできる。工作あるあるだが、「設定を間違えて詰んだ」ときの逃げ道は、作っている最中は面倒でも、後になって必ず自分を助けてくれる。

## 結局、動いたのか

技術的には、ADCの分圧回路もHMAC署名もMatterのエンドポイント定義も、それぞれ調べればどこかに情報がある話だ。でも、それを1枚のESP32-C3の上に、動くものとしてまとめ上げる作業には、それなりの手間と、そして謎の達成感がある。今回もその達成感を味わうために、1日を溶かしてしまった。
