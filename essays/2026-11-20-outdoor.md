# ベランダ環境センサーを無線で切り離す 〜ESP-NOWと電池駆動で挑む屋外計測〜

2026-11-20

## 窓の外のデータをどう引っ張るか

部屋の中でエアコンの自動制御やスマートホーム化を進めていくと、どうしても欲しくなるのが「外の環境データ」だ。

特に、ベランダの日当たり具合（照度）や外気温がリアルタイムに分かれば、「日差しが強くなってきたからカーテンを閉める」「外気の方が涼しくなったから換気扇を回す」といった、一歩進んだ自動化が可能になる。

しかし、室内から外の環境を測ろうとすると、窓ガラスの断熱性や日射カットフィルム、反射の影響を受けて正確な値が取れない。かといって窓サッシの隙間にフラットケーブルを通すのは見た目も悪く、雨水の侵入や断線のリスクもつきまとう。

「それならいっそ、ベランダに小さな電池駆動の子機を置き、無線で室内の親機へデータを飛ばせばいいのではないか」――そう思い立ち、屋外環境センサー子機の分離計画をスタートさせた。

## Wi-Fiではなく、あえて「ESP-NOW」を選ぶ理由

電池駆動のIoTデバイスを作るうえで、最大の敵となるのが無線通信の電力消費だ。

通常のWi-Fi接続は、スリープから復帰したあとにアクセスポイントを探索し、暗号化ハンドシェイクを行い、DHCPでIPアドレスを取得するまでに数秒から十数秒の時間がかかってしまう。その間、マイコンはずっと80〜100mA前後の電流を消費し続けるため、乾電池駆動ではあっという間にバッテリーが干上がってしまう。

そこで白羽の矢を立てたのが、Espressif独自の無線通信プロトコル **ESP-NOW** である。

ESP-NOWは、2.4GHzのWi-Fi物理層を使いながらも、通常のネットワーク接続シーケンスを一切踏まない。あらかじめ登録した相手のMACアドレス宛てにダイレクトにパケットを投げ、即座にハードウェアACKを受け取って終了する。その所要時間はわずか **10〜20ミリ秒（0.01〜0.02秒）** だ。

これだけの短時間で済むなら、送信時の一瞬だけ電流を食うものの、大半の時間はマイコンをディープスリープ（約40µA）させておくことができる。5分に1回の測定送信であれば、電池寿命を圧倒的に引き延ばせる。

```
┌──────────────────────────────────────┐
│  ベランダ（電池駆動）                │
│  [子機: XIAO ESP32-C3]               │
│    - CdS 照度センサー                │
│    - B3950 サーミスタ (外気温)       │

└──────────────────┬───────────────────┘
```

## ルーターのチャンネル変更にどう追従するか

しかし、ここでひとつ技術的な工夫が必要になる。

室内の親機（ESP32-C3）は、Google HomeやMatter連携、Webダッシュボードのために自宅のWi-Fiルーターへ常時接続（STAモード）している。Wi-Fiルーターは起動時や電波の混雑状況によって、使用チャンネル（1〜13ch）を自動で切り替えることがある。

ESP-NOWは親機と同じチャンネルで電波を出さないと届かない。かといって、子機側が毎回1〜13チャンネルを総当たりスキャンしていては、起動時間が伸びて省電力の恩恵が薄れてしまう。

そこで考えたのが、**RTC Fast Memory** を利用した「チャンネル自動追従とフェイルオーバー」の仕組みだ。

1. **チャンネルの保持**:
   子機内で `RTC_DATA_ATTR uint8_t s_cached_channel = 1;` として保持しておく。RTCメモリはディープスリープ中も給電が維持されるため、前回のチャンネル番号がそのまま残る。
2. **通常時（99.9%）の最速送信**:
   起床したら、キャッシュされたチャンネルで親機宛てに送信する。親機からハードウェアACK（`ESP_NOW_SEND_SUCCESS`）が返れば、わずか10〜20msで任務完了、即座にスリープへ潜る。
3. **フェイルオーバー時（ルーターのチャンネル変更時）**:
   もしACKが返ってこなかった場合（ルーター側がチャンネルを切り替えたとき）だけ、Channel 1 から 13 まで順次パケットを送信して親機を探す。無事にACKが返ったチャンネルを新しい `s_cached_channel` に上書き保存し、次回以降はその番号を使う。

この仕掛けを入れておけば、通常時は無駄な電力を使わず、万一のルーター再起動やチャンネル変更時にも自律して親機を見失わずに済む。

送受信するパケットも、下記のようにわずか12バイトの極小データ構造体にまとめた。

```c
typedef struct __attribute__((packed)) {
    float lux;              // ベランダ照度 (Lux, 0.0 〜 100000.0)
    float temp_celsius;     // ベランダ外気温 (摂氏 ℃, -20.0 〜 80.0)
    float battery_voltage;  // 子機の電池電圧 (V, 例: 2.95)
} esp_now_sensor_packet_t;
```

## ハードウェアの選定と役割分担

子機側のマイコンには、低暗電流レギュレータを搭載し、ディープスリープ電流が約40µAに抑えられている **Seeed Studio XIAO ESP32C3**（または SuperMini）を採用する。USBシリアル変換ICが載っていないため、無駄な待機電流を極限まで削れるのが頼もしい。

センサーには、直射日光下の強い光から夕暮れの薄暗さまで対応するCdSセルと、外気温用のB3950サーミスタを配置。さらに乾電池の電圧降下を捉えるための分圧抵抗を設け、電池残量も子機から親機へ送る設計にした。

| 設置場所 | デバイス・部品 | 接続・仕様 | 役割 |
| :--- | :--- | :--- | :--- |
| **子機（ベランダ）** | XIAO ESP32C3<br>単4電池×2本 (3.0V) | GPIO1: CdS照度<br>GPIO3: B3950外気温<br>GPIO0: 電池電圧測定 | 5分ごとに起床して計測・ESP-NOW送信後、即スリープ（約40µA） |
| **親機（室内）** | ESP32-C3 開発ボード<br>USB常時給電 | GPIO3: B3950室内温度<br>GPIO9: 初期化ボタン | 常時Wi-Fi接続、ESP-NOW受信、Matterサーバー、Web UI |

室内側にある親機にもサーミスタを直結しているのがポイントだ。外のデータを受けるだけでなく、自分自身でも室内温度を計測することで、親機単独で「部屋の中」と「ベランダの外」の両方の温度を比較・管理できるようになる。

## Matter over Wi-Fi でGoogle Homeに束ねる

親機に集まったデータは、**Matter over Wi-Fi** を使ってGoogle Homeへ連携する。

親機はMatterサーバーとして振る舞い、1台のデバイスの中に以下の3つのエンドポイントを同居させて公開する（マルチエンドポイント構成）。

- **Endpoint 1 (Light Sensor)**: ベランダ照度（子機から受信）
- **Endpoint 2 (Temperature Sensor)**: 室内温度（親機直結サーミスタ）
- **Endpoint 3 (Temperature Sensor)**: ベランダ外気温（子機から受信）

Google Homeアプリを開くと、ひとつのマイコンから「リビングの温度」「ベランダの外気温」「ベランダの明るさ」がそれぞれ独立したタイルとして整然と並ぶ。

クラウド依存ではなくローカルのMatter通信で同期されるため、レスポンスも極めて軽快だ。Webダッシュボード上でも室内外の温度差や子機のバッテリー残量が一目で把握できるようにする。

## 単4乾電池2本で2年戦えるか？

最後に、気になる子機の電池寿命を試算してみよう。

- **スリープ時電流**: 約 40 µA
- **送信時電流**: 平均約 100 mA（所要時間はわずか約 0.02 秒）
- **測定頻度**: 5分に1回（1日 288回）

これを元に1日あたりの消費電力量を計算すると、以下のようになる。

$$\text{1日の消費電力量} \approx (40\,\mu\text{A} \times 24\,\text{h}) + \left(100\,\text{mA} \times \frac{0.02\,\text{s}}{3600\,\text{s}} \times 288\right) \approx 0.96\,\text{mAh} + 0.16\,\text{mAh} = 1.12\,\text{mAh/日}$$

単4形アルカリ乾電池2本（直列3.0V）の実効容量を控えめに約 800〜900 mAh と見積もると：

$$\frac{800\,\text{mAh}}{1.12\,\text{mAh/日}} \approx 714\,\text{日} \quad (\mathbf{約\,1.9\,年})$$

乾電池の自己放電や真冬の低温による容量低下を考慮しても、**1年半から2年近くはノーメンテナンス** でベランダに放置できる見込みが立った。2年に1回、電池を入れ替えるだけで済むなら実用上十分すぎる。

## 小さな箱をベランダへ送り出す楽しさ

窓枠の配線という物理的な制約を、ESP-NOWという軽量な無線プロトコルで乗り越える。そして低消費電力設計を突き詰め、最終的にはMatter経由で部屋の空調自動化へ繋げていく。

単なる仕様書を眺めるだけでなく、「どうすれば乾電池で何年も動かせるか」「ルーターの気まぐれにどう立ち向かうか」を一つずつ紐解いていく過程は、組み込みDIYならではの醍醐味だ。

防滴ケースに収めた小さな子機をベランダの日陰に送り出し、室内からそのデータを受け取る日が今から待ち遠しい。
